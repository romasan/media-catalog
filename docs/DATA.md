# Данные: хранение, форматы, экспорт/импорт

## Расположение данных

Директория данных создаётся автоматически при запуске приложения:

```
<userData>/
└── media-catalog-data/
    ├── catalog.db          — JSON-база данных
    └── thumbnails/         — сгенерированные превью
```

- В **режиме разработки** `userData` находится рядом с проектом.
- В **production** — в стандартной папке данных пользователя ОС (macOS: `~/Library/Application Support/<app>`, Windows: `%APPDATA%`, Linux: `~/.config`).

## Структура catalog.db

Файл `catalog.db` — JSON следующей структуры:

```json
{
  "catalogs": [
    {
      "id": "uuid",
      "path": "/absolute/path/to/folder"
    }
  ],
  "mediaFiles": [
    {
      "id": "uuid",
      "path": "/absolute/path/to/file.jpg",
      "name": "file.jpg",
      "type": "photo" | "video",
      "size": 123456,
      "createdAt": 1710000000000,
      "modifiedAt": 1710000000000,
      "catalogId": "uuid",
      "thumbnailPath": "/path/to/thumbnails/abc123.jpg"
    }
  ],
  "tags": [
    {
      "id": "uuid",
      "name": "Отпуск",
      "lastUsedAt": 1710000000000
    }
  ],
  "mediaTags": [
    {
      "mediaId": "uuid",
      "tagId": "uuid"
    }
  ]
}
```

### Коллекции и типы

| Коллекция | Тип | Описание |
|-----------|-----|---------|
| `catalogs` | `Catalog[]` | Добавленные пользователем папки для сканирования |
| `mediaFiles` | `MediaFile[]` | Все найденные медиафайлы |
| `tags` | `Tag[]` | Созданные теги |
| `mediaTags` | `MediaTagRelation[]` | Связи многие-ко-многим между файлами и тегами |

Типам соответствуют интерфейсы в `src/shared/types.ts`.

### Механизм сохранения

- Запись с **дебаунсом 300 мс** (класс `Database.save()`).
- **Атомарность**: сначала запись во временный файл `catalog.db.tmp`, затем `fs.renameSync(tempPath, dbPath)`. Сбой в момент записи не повреждает основную базу.
- При загрузке проверяется валидность структуры (все 4 коллекции должны быть массивами); при ошибке — база сбрасывается в пустую.

### Поля подробно

- **`MediaFile.createdAt`** — время создания файла (`birthtime`), либо `mtime` как запасной вариант, либо `Date.now()` при ошибке.
- **`MediaFile.modifiedAt`** — `mtime` файла. Выступает как признак изменённого файла при сканировании (сравнивается вместе с `size`).
- **`Tag.lastUsedAt`** — timestamp последнего применения тега к файлу. Используется для сортировки тегов: более «свежие» теги выше; теги без использований (`0`) — в конце списка.
- **`thumbnailPath`** — абсолютный путь к JPG-превью (или пустая строка, если превью ещё не сгенерировано).

## Превью (thumbnails)

### Генерация

- Генерируются **асинхронно** через `ffmpeg-static` сразу после сканирования.
- Размер: **400×400**, квадрат, JPEG.
- Для **видео** извлекается кадр с 0.5 секунды.
- Для **фото** — ресайз с кропом.
- Очередь обрабатывается **последовательно**: один ffmpeg-процесс за раз.

### Именование

Имя файла превью вычисляется из полного пути исходника:

```
<hash(path)>.<ext>.jpg
```

`hash` — 32-битный строковый хэш пути (функция `hashString`, FNV-подобная). Это позволяет:
- детерминированно находить превью по пути файла;
- избегать конфликтов имён для файлов в разных папках с одинаковым именем;
- переиспользовать превью при повторном сканировании (кэш).

### Кэш и удаление

- Если превью уже существует в `thumbnails/` — повторная генерация не выполняется.
- При удалении файла/каталога `deleteThumbnailsForFiles` удаляет превью **двумя способами**:
  1. по сохранённому `thumbnailPath` в базе;
  2. по вычисленному хэшу пути — на случай, если `thumbnailPath` не был записан (например, файл удалён до готовности превью).

## События прогресса

| Событие | Данные | Описание |
|---------|--------|---------|
| `IPC.OnThumbnailProgress` | `{ total, processed }` | Отправляется не чаще 1 раза в 200 мс |
| `IPC.OnThumbnailReady` | `{ mediaId, thumbnailPath }` | Отправляется сразу после готовности каждого превью |

## Метатеги

Метатеги — автоматически вычисляемые теги, которые **не хранятся в базе** и **не экспортируются**. Они вычисляются на лету в main-процессе (`src/main/ipc-handlers.ts`) для каждого медиафайла.

### Группы метатегов

| Группа | Метатег | Правило |
|--------|---------|---------|
| **Год** | `2025`, `2026`, ... | Год из `createdAt` файла |
| **Время года** | `зима`, `весна`, `лето`, `осень` | Зависит от месяца и дня `createdAt` |
| **Тип файла** | `фото`, `видео` | Из `MediaFile.type` |

### Правила времён года

| Сезон | Период |
|-------|--------|
| **Зима** | 1 декабря — 28/29 февраля включительно |
| **Весна** | 1 марта — 13 мая |
| **Лето** | 14 мая — 31 августа |
| **Осень** | 1 сентября — 30 ноября |

### Отображение

- В превью-режиме (FullscreenViewer) метатеги отображаются **серым цветом** отдельно от обычных тегов.
- В TagManagerPopup метатеги показываются в самом конце, **не построчно**, а друг за другом (горизонтальные ряды), разбитые на группы: год → время года → тип файла.
- Метатег нельзя удалить или снять с файла.
- Клик по метатегу добавляет его в фильтр на основном экране так же, как обычный тег.

### Получение

Канал `meta:tags:get` возвращает все уникальные метатеги с количеством файлов по каждому.

## Экспорт/импорт

### Формат файла экспорта

JSON-файл:
```json
{
  "version": 1,
  "exportedAt": 1710000000000,
  "catalogs": [ ... ],
  "tags": [ ... ],
  "mediaTags": [ ... ],
  "files": [
    {
      "path": "/abs/path/file.jpg",
      "createdAt": 1710000000000,
      "modifiedAt": 1710000000000,
      "size": 123456
    }
  ]
}
```

Экспортируются:
- каталоги (пути);
- теги (без связей с id файлов — связи восстанавливаются по путям после импорта);
- связи `mediaTags`;
- список файлов (без id, без `thumbnailPath`).

### Экспорт

Канал `IPC.ExportData`. Путь по умолчанию: `media-catalog-export-<timestamp>.json`. Если путь не передан — открывается системный диалог сохранения.

### Импорт

Канал `IPC.ImportData`. Алгоритм:

1. **Чтение и валидация** JSON (обязателен массив `catalogs`).
2. **Добавление каталогов** — идемпотентно, по нормализованному пути. Если каталог уже существует в базе — пропускается.
3. **Восстановление тегов** — по имени (без учёта регистра). Для существующего тега `lastUsedAt` берётся максимум; для нового — создаётся и проставляется `lastUsedAt` из файла импорта.
4. **Сохранение «отложенных» связей тегов** во временные глобальные переменные `global.__pendingImportMediaTags` / `global.__pendingImportFilePaths`.
5. **Запуск полного сканирования** — каталоги просканируются, файлы добавятся в базу с новыми id.
6. **Восстановление связей тегов** (`populateMediaTagsAfterImport` в `main/index.ts`): после сканирования пути сопоставляются с id файлов (нормализация через `path.normalize` и `path.resolve`), и связи применяются через `database.applyTag`.

> ⚠️ **Важно**: файлы при импорте не копируются. Импортируются только метаданные и пути. Если файлов нет на диске — они не будут добавлены, а связи тегов не восстановятся.

## Каналы IPC

### Запросы (renderer → main)

| Канал | Параметры | Результат |
|-------|-----------|-----------|
| `catalogs:get` | — | `Catalog[]` |
| `catalogs:add` | — (диалог выбора папки в main) | `Catalog[]` |
| `catalogs:remove` | `catalogId: string` | — |
| `catalogs:stats` | — | `CatalogStats[]` |
| `scan:start` | — | `ScanResult` |
| `media:get` | `MediaFilters { filter?, limit?, offset? }` | `{ items: MediaFile[]; total: number }` |
| `media:tags:get` | `mediaId: string` | `Tag[]` |
| `media:stream:url` | `MediaStreamRequest { filePath, type }` | `string` (URL `media-stream://...`) |
| `meta:tags:get` | — | `MetaTagInfo[]` (год, сезон, тип файла; с количеством файлов) |
| `tags:get` | — | `TagSearchResult[]` (с счётчиками, сортировка по `lastUsedAt`) |
| `tags:search` | `query: string` | `TagSearchResult[]` (до 30, по подстроке без учёта регистра) |
| `tags:create` | `name: string` | `Tag[]` |
| `tags:delete` | `tagId: string` | — |
| `tags:apply` | `mediaId, tagId: string` | — |
| `tags:remove-from-media` | `mediaId, tagId: string` | — |
| `data:export` | — (диалог сохранения в main) | — |
| `data:import` | — (диалог открытия в main) | `ScanResult | null` |

### События (main → renderer)

| Канал | Направление | Данные |
|-------|------------|--------|
| `scan:complete` | main → renderer | `ScanResult` |
| `thumbnails:progress` | main → renderer | `ThumbnailProgress { total, processed }` |
| `thumbnails:ready` | main → renderer | `{ mediaId, thumbnailPath }` |

Все константы каналов определены в `src/shared/ipc.ts`.
