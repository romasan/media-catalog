# Данные приложения

## Каталог данных

Все runtime-данные лежат в одном каталоге:

| Платформа | Путь по умолчанию |
|-----------|-------------------|
| macOS | `~/Library/Application Support/MediaCatalog/` |
| Windows | `%APPDATA%\MediaCatalog\` |
| Linux | `~/.local/share/MediaCatalog/` |

```
<каталог данных>/
├── catalog.sqlite      # база данных приложения
├── catalog.sqlite-wal  # журнал WAL (создаётся автоматически)
├── catalog.sqlite-shm  # разделяемая память WAL
└── thumbnails/         # сгенерированные превью (400×400 JPEG)
```

Каталог можно переопределить ключом `--data-dir <путь>` — это удобно для
переносимой сборки и для запуска нескольких независимых копий приложения.

## Схема базы данных

Файл `catalog.sqlite` — **SQLite в режиме WAL** (`user_version = 1`). Версия схемы
проверяется при открытии: база, созданная более новой версией приложения, не
открывается, чтобы не испортить данные.

### `catalogs` — добавленные пользователем папки

| Колонка | Тип | Описание |
|---------|-----|----------|
| `id` | TEXT PK | Идентификатор (UUID без фигурных скобок) |
| `path` | TEXT UNIQUE | Абсолютный путь без символических звеньев |

### `media` — проиндексированные файлы

| Колонка | Тип | Описание |
|---------|-----|----------|
| `id` | TEXT PK | Идентификатор файла |
| `path` | TEXT UNIQUE | Абсолютный путь |
| `name` | TEXT | Имя файла |
| `kind` | TEXT | `photo` или `video` |
| `size` | INTEGER | Размер в байтах |
| `created_at` | INTEGER | Дата создания файла, мс (с откатом на `modified_at`) |
| `modified_at` | INTEGER | Дата изменения файла, мс |
| `catalog_id` | TEXT | Каталог-владелец (NULL, если каталог удалён) |
| `thumbnail_path` | TEXT | Путь к превью; пустая строка — превью ещё нет |
| `thumbnail_retries` | INTEGER | Неудачные попытки генерации превью |
| `captured_at` | INTEGER | Дата съёмки, мс; **NULL — не вычислялась**, **0 — не найдена** |

Индексы: `idx_media_modified` по `modified_at DESC` (сортировка списка),
`idx_media_catalog` по `catalog_id` (статистика и удаление каталога).

### `tags` — пользовательские теги

| Колонка | Тип | Описание |
|---------|-----|----------|
| `id` | TEXT PK | Идентификатор тега |
| `name` | TEXT UNIQUE | Имя в нижнем регистре, без пробелов по краям |
| `last_used_at` | INTEGER | Время последнего применения, мс (0 — не применялся) |

### `media_tags` — связи «файл ↔ тег»

| Колонка | Тип | Описание |
|---------|-----|----------|
| `media_id` | TEXT | Ссылка на `media.id` (каскадное удаление) |
| `tag_id` | TEXT | Ссылка на `tags.id` (каскадное удаление) |

Первичный ключ — пара (`media_id`, `tag_id`), поэтому повторное применение тега
ничего не меняет.

## Целостность данных

Правила соблюдаются в `CatalogDatabase`:

- **Нормализация имён тегов.** Имя обрезается по краям и приводится к нижнему
  регистру. При открытии базы дубликаты («Отпуск», «отпуск») объединяются:
  связи переносятся на выживший тег, время последнего применения берётся
  максимальное, лишние записи удаляются.
- **Удаление каталога** убирает его файлы и связи этих файлов с тегами.
- **Удаление файла** (файл исчез с диска) убирает его связи с тегами.
- **Очистка осиротевших тегов.** Тег удаляется, если он уже применялся
  (`last_used_at > 0`), но больше не связан ни с одним файлом. Теги, созданные
  и ещё не применённые, сохраняются.
- **Снятие тега с файла** сбрасывает `last_used_at` в 0, если тег больше нигде
  не используется, но сам тег не удаляет.

## Метатеги

Метатеги **не хранятся в базе** — они вычисляются из свойств файла:

| Вид | Идентификатор | Значение |
|-----|---------------|----------|
| Год | `meta:year:<год>` | Год даты изменения файла (локальное время) |
| Время года | `meta:season:<сезон>` | `зима`, `весна`, `лето`, `осень` по месяцу даты изменения |
| Тип файла | `meta:type:<фото\|видео>` | По расширению файла |
| Без тега | `meta:untagged` | Файлы, у которых нет ни одного пользовательского тега |

Сезоны: декабрь–январь–февраль — зима, март–май — весна, июнь–август — лето,
сентябрь–ноябрь — осень.

В экспорт метатеги не попадают: после импорта они вычисляются заново.

## Превью

- Размер — 400×400 пикселей, JPEG. Кадр масштабируется с сохранением пропорций
  и обрезается по центру, поэтому превью всегда квадратное.
- Для видео берётся кадр на 0.5-й секунде.
- Имя файла: `<хэш пути><расширение исходника>.jpg`,
  например `1ho96a.jpg.jpg`. Превью хранятся отдельно от исходников.
- Хэш повторяет алгоритм версии 1.x (см. [ARCHITECTURE.md](ARCHITECTURE.md)),
  поэтому **существующий кэш превью совместим**: после обновления приложения
  ничего не перегенерируется.
- Превью удаляются при удалении файла из базы или каталога из списка.
- Неудачная генерация фиксируется в `thumbnail_retries`; после первой неудачи
  файл пробуется ещё раз, после второй — больше не ставится в очередь.

## Экспорт и импорт

Экспорт переносит каталоги, теги и связи между устройствами. Формат — JSON:

```json
{
  "version": 1,
  "exportedAt": 1770000000000,
  "catalogs": [{ "id": "…", "path": "/photos" }],
  "tags": [{ "id": "…", "name": "отпуск", "lastUsedAt": 1770000000000 }],
  "files": [
    {
      "path": "/photos/a.jpg",
      "name": "a.jpg",
      "size": 123456,
      "createdAt": 1760000000000,
      "modifiedAt": 1765000000000,
      "kind": "photo",
      "capturedAt": 1762000000000
    }
  ],
  "mediaTags": [{ "file": "/photos/a.jpg", "tag": "отпуск" }]
}
```

Особенности:

- **Связи выражаются путями и именами, а не идентификаторами.** После импорта на
  другом устройстве идентификаторы файлов будут другими, а пути и имена тегов —
  те же.
- `capturedAt: null` означает «дата съёмки не вычислялась» и отличается от `0`.
- Экспорт пишется через временный файл с последующим переименованием: прерванная
  запись не оставляет обрезанный JSON на месте готового файла.
- Импорт добавляет каталоги, создаёт отсутствующие теги, восстанавливает связи и
  запускает сканирование, чтобы файлы появились в базе.

## Обновление с версии 1.x

Версия 1.x хранила данные в `media-catalog-data/catalog.db` в формате **JSON**, а
не SQLite. Нативная версия не читает этот формат: база создаётся заново, после
чего достаточно снова добавить папки — сканирование найдёт файлы, а
**существующие превью подхватятся из общего кэша**, если указать тот же каталог
данных через `--data-dir`.

Для переноса тегов из версии 1.x:

1. В старой версии выполните «Экспорт данных» — получится JSON.
2. В новой версии импортируйте этот файл. Формат экспорта совместим: новая версия
   читает `catalogs`, `tags` и `mediaTags` из файла версии 1.x, связи
   восстанавливаются по путям и именам тегов.

Файлы превью в старой версии лежали в `<каталог данных>/thumbnails/` с теми же
именами, поэтому при совпадении каталога данных они используются без
перегенерации.
