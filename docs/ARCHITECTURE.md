# Архитектура приложения

## Обзор

Media Catalog 2.0 — **нативное приложение на C++20 и Qt 6**, собираемое из одного
кода для macOS, Windows и Linux. Вместо трёх процессов Electron приложение состоит
из трёх слоёв внутри одного процесса:

```
┌───────────────────────────────────────────────────────────────┐
│                    mediacatalog (один процесс)                │
│                                                               │
│  ┌──────────────────┐   ┌──────────────────┐   ┌───────────┐  │
│  │   Ядро (C++)     │   │  Слой приложения │   │  QML UI   │  │
│  │   mc_core        │   │  src/app/        │   │  qml/     │  │
│  │                  │   │                  │   │           │  │
│  │  CatalogDatabase │◄──│  MediaListModel  │◄──│ MediaGrid │  │
│  │  MediaScanner    │   │  TagListModel    │   │ Viewer    │  │
│  │  ThumbnailGen.   │   │  AppController   │   │ Попапы    │  │
│  │  MetadataReader  │   │                  │   │           │  │
│  │  MediaLibrary    │──►│  сигналы Qt      │──►│  биндинги │  │
│  └──────────────────┘   └──────────────────┘   └───────────┘  │
│           │                                                   │
│           ├── SQLite (catalog.sqlite)                         │
│           ├── файловая система (сканирование)                 │
│           └── ffmpeg / ffprobe (превью и метаданные видео)    │
└───────────────────────────────────────────────────────────────┘
```

### Три слоя

| Слой | Директория | Роль |
|------|-----------|------|
| **Ядро** | `src/core/` | Логика без зависимости от интерфейса: база данных, сканирование, превью, метаданные, фильтрация, экспорт/импорт. Собирается в статическую библиотеку `mc_core` и покрыто консольными тестами. |
| **Приложение** | `src/app/` | Модели Qt для QML и фасад `AppController`. Здесь нет работы с файлами и базой — только адаптация ядра к интерфейсу. |
| **Интерфейс** | `qml/` | Декларативные экраны на Qt Quick: сетка, полноэкранный просмотр, фильтр, попапы. Общается с C++ только через свойства, сигналы и `Q_INVOKABLE`-методы. |

Такое разделение позволяет тестировать всю логику без графической среды и
переиспользовать ядро в других оболочках.

## Ядро

```
src/core/
├── MediaTypes.h        # Каталог, MediaFile, Tag, MetaTag, ScanResult, FilterCondition
├── Paths.h/.cpp        # Каталог данных, путь к базе, имя файла превью
├── PathHash.h/.cpp     # Хэш пути для имени превью (совместим с версией 1.x)
├── MediaFormats.h/.cpp # Поддерживаемые расширения и тип файла
├── CatalogDatabase.h/.cpp   # SQLite: схема, запросы, целостность
├── MediaScanner.h/.cpp      # Рекурсивный обход и синхронизация с базой
├── ThumbnailGenerator.h/.cpp# Очередь превью и пул процессов ffmpeg
├── MetadataReader.h/.cpp    # EXIF для фото, creation_time для видео
├── MetaTags.h/.cpp          # Вычисляемые метатеги (год, сезон, тип, «без тега»)
├── MediaFilter.h/.cpp       # Фильтрация по тегам и метатегам

```

### MediaLibrary — фасад ядра

`MediaLibrary` владеет базой, сканером и генератором превью и публикует изменения
сигналом `libraryChanged()`. Модели и интерфейс не обращаются к базе напрямую:
они читают данные через методы фасада и перестраиваются по сигналу.

Разделение обязанностей:

| Объект | Ответственность |
|--------|-----------------|
| `CatalogDatabase` | Чтение и запись SQLite, целостность связей, нормализация тегов |
| `MediaScanner` | Обход файловой системы, добавление, обновление и удаление записей |
| `ThumbnailGenerator` | Очередь превью, пул процессов ffmpeg, повторные попытки |
| `MetadataReader` | Дата съёмки: EXIF в JPEG/TIFF, `creation_time` в контейнерах видео |
| `MediaLibrary` | Организация работы: сканирование в фоне, запросы, экспорт/импорт |

### Хранение

Единственный источник истины — файл SQLite в каталоге данных приложения
(подробности в [DATA.md](DATA.md)). Состояние интерфейса (выделение, фильтр,
позиция прокрутки) в базе не хранится.

## Слой приложения

| Класс | Роль |
|-------|------|
| `MediaListModel` | `QAbstractListModel` со списком файлов для сетки. Отдаёт готовые для QML роли: идентификатор, имя, путь, признак видео, размер, даты, ссылку на превью, ссылку на оригинал, признак выделения. |
| `TagListModel` | Список тегов либо метатегов, с фильтром по подстроке. Используется менеджером тегов и автодополнением. |
| `AppController` | Фасад для QML: владеет моделями, выделением, диалогами, форматированием дат и размеров. |

### Почему превью не сбрасывает модель

Готовые превью приходят по одному, по мере работы ffmpeg. Если на каждое превью
перестраивать модель целиком, сетка будет терять позицию прокрутки. Поэтому
`MediaListModel` обрабатывает сигнал `thumbnailReady` точечно: находит строку по
идентификатору, обновляет её данные и emits `dataChanged` только для неё.

## Потоки и синхронизация

| Работа | Где выполняется |
|--------|-----------------|
| Сканирование файловой системы | Один поток из `QThreadPool` (`m_scanPool`, максимум 1 задача) |
| Генерация превью | Пул `QThreadPool` внутри `ThumbnailGenerator`: по одному процессу ffmpeg на ядро |
| Чтение метаданных | `QThreadPool` на 2 потока (`m_metadataPool`) |
| Модели и интерфейс | Главный поток |

Правила, которые соблюдаются в коде:

1. **У каждого потока своё соединение с базой.** `QSqlDatabase` нельзя
   использовать из нескольких потоков, поэтому `CatalogDatabase` выдаёт
   соединение на поток (`threadConnection()`): оно создаётся при первом
   обращении и хранится в `QThreadStorage`. Режим WAL позволяет читать и писать
   параллельно, поэтому сканирование в фоне не блокирует интерфейс.
2. **Интерфейс обновляется только в главном потоке.** Модели перестраиваются по
   сигналам, то есть всегда в потоке интерфейса; результат фоновой работы
   возвращается сигналом или через `QMetaObject::invokeMethod` с типом соединения
   `Qt::QueuedConnection`.
3. **Сканирование не идёт параллельно самому себе.** Если сканирование уже
   выполняется, запрос ставится в очередь и запускается после завершения
   текущего (`m_scanQueued`).
4. **Завершение явное.** `MediaLibrary::shutdown()` обрывает связи с рабочими
   объектами, дожидается сканирования и чтения метаданных, останавливает пул
   превью (его задачи трогают базу, поэтому она должна быть жива до их
   завершения) и снимает с очереди уже накопившиеся сигналы. Деструктор вызывает
   `shutdown()`, поэтому выход из приложения не оставляет работающих потоков.

### Прогресс

`ThumbnailGenerator::progress` сообщает общее число задач и число обработанных.
`MediaLibrary` превращает это в долю готовности и публикует
`thumbnailProgressChanged`. Интерфейс обновляет полосу прогресса не чаще
нескольких раз в секунду.

## Генерация превью

1. Сканер собирает файлы без превью (новые и те, что остались без превью после
   прошлого запуска) и ставит их в очередь генератора.
2. Очередь дедуплицируется по пути: файл не может попасть в работу дважды.
3. Пул запускает ffmpeg с параметрами
   `-threads 1 -i <файл> [-ss 0.5] -vf scale=400:400:...,crop=400:400 -frames:v 1 <выход>`.
   Однопоточность внутри процесса означает, что загрузку ядер даёт число
   процессов, а не многопоточность ffmpeg.
4. Имя файла превью — хэш пути (см. ниже), расширение исходника и суффикс `.jpg`.
5. Успешный результат записывается в базу (`update_thumbnail`) и публикуется
   сигналом `thumbnailReady`.
6. При неудаче попытка фиксируется в базе; разрешён ровно один повтор, после
   чего файл больше не ставится в очередь. Частично записанный файл удаляется,
   чтобы битая картинка не «залечила» превью.

### Совместимость имён превью

Имя файла превью повторяет алгоритм версии 1.x до бита:

```js
let hash = 0;
for (let i = 0; i < input.length; i++) {
  hash = ((hash << 5) - hash) + input.charCodeAt(i);
  hash |= 0;
}
return Math.abs(hash).toString(36);
```

Реализация (`PathHash.cpp`) учитывает три особенности JavaScript: кодовая единица
UTF-16 вместо Unicode-символа, усечение до знакового 32-битного и случай
`INT32_MIN`, для которого `Math.abs` даёт 2³¹. Совпадение проверяется тестами по
эталонным значениям. Благодаря этому кэш превью, созданный старой версией,
переиспользуется без перегенерации.

## Сканирование

1. Для каждого каталога выполняется рекурсивный обход. Пропускаются скрытые
   папки (начинающиеся с точки), `@eaDir` и `System Volume Information`.
2. Файл приписывается **самому глубокому** каталогу, который его содержит. Это
   важно, когда один добавленный каталог вложен в другой: иначе файл попал бы
   в базу дважды.
3. Записи без изменений не перезаписываются: обновление происходит только при
   изменении даты модификации, размера или каталога-владельца.
4. Файлы, которых больше нет на диске, удаляются из базы вместе со связями
   тегов; их превью стираются.
5. Файлы, оставшиеся без превью, снова ставятся в очередь.

## Метаданные

| Тип файла | Источник даты съёмки |
|-----------|----------------------|
| JPEG, TIFF | EXIF: `DateTimeOriginal` → `CreateDate` → `ModifyDate` |
| Видео (mp4, mov, mkv и др.) | `format_tags=creation_time` через `ffprobe` |

EXIF-парсер написан в проекте (`MetadataReader.cpp`) — внешние зависимости не
нужны. Дата из EXIF читается как локальное время (часового пояса в EXIF нет),
`creation_time` контейнера трактуется как UTC.

Дата съёмки запрашивается лениво при открытии полноэкранного просмотра и
сохраняется в базе. Состояния различаются: `NULL` — «ещё не вычислялась»,
`0` — «вычислялась, дата не найдена». Это избавляет от повторного чтения файлов.

### Виртуализация сетки

`GridView` создаёт делегаты только для видимых ячеек, поэтому прокрутка остаётся
плавной и на больших каталогах. Размер ячейки подбирается так, чтобы карточки
занимали всю ширину окна и были не меньше `Theme.minCardSize` (100 px).

Диапазон дат видимых карточек вычисляется по геометрии: индексы первой и
последней видимых строк считаются из `contentY`, числа колонок и высоты ячейки.
Так результат не зависит от того, какие делегаты успел создать `GridView`.

## Сборка и упаковка

- **CMake 3.21+** и **Qt 6.5+** (Core, Gui, Qml, Quick, QuickControls2, Sql,
  Multimedia, Test).
- Ядро собирается в `mc_core`, приложение — в `mediacatalog` с QML-модулем
  `MediaCatalog`, тесты — в `mc_core_tests` и `mc_model_tests`.
- Для переносимого пакета: `ninja deploy` (запускает `macdeployqt` или
  `windeployqt`) и `cpack`. Подробности — в [BUILD.md](BUILD.md).

## Безопасность

- Приложение не содержит сетевого кода и не открывает портов.
- SQL-запросы параметризованы; имена таблиц и колонок в них не подставляются.
- Работа с файлами ограничена каталогами, которые явно добавил пользователь,
  и каталогом данных приложения.
- Внешний процесс — только `ffmpeg`/`ffprobe`, запускаемые с фиксированным
  набором аргументов без участия оболочки (`QProcess` без `shell`).
- Экспорт пишется через временный файл с последующим переименованием: прерванный
  экспорт не оставляет обрезанный JSON на месте готового.
