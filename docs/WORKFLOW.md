# Сценарии работы приложения

## Запуск приложения

1. Electron стартует, регистрируется привилегированный протокол `media-stream://`.
2. Создаются `Database`, `ThumbnailGenerator`, `CatalogScanner`.
3. Вызывается `populateMediaTagsAfterImport()` — восстанавливаются отложенные связи тегов, если был импорт данных (см. [DATA.md](DATA.md#импорт)).
4. Регистрируются IPC-обработчики.
5. Создаётся окно.
6. Через 1 секунду запускается **фоновое сканирование** каталогов.

Renderer при монтировании загружает: каталоги, статистику, теги и медиа (см. [ARCHITECTURE.md](ARCHITECTURE.md#загрузка-приложения)).

## Сканирование каталогов

### Ручное

1. Пользователь открывает меню (BurgerMenu) → «Управление каталогами».
2. Нажимает «Добавить каталог».
3. Открывается системный диалог выбора папки.
4. После выбора папка добавляется в базу (`addCatalog`), через 100 мс запускается `runScan()`.
5. Сканирование проходит рекурсивно; новые файлы попадают в базу; для них ставится очередь генерации превью.
6. Renderer получает событие `scan:complete` → тост «Добавлено файлов: N» → перезагрузка каталогов, статистики и медиа.
7. Прогресс-бар превью показывает генерацию.

### Автоматическое

- При **старте приложения** (через 1 секунду).
- При **импорте данных** (после добавления каталогов).
- После **ручного запуска** через «Сканировать» (кнопка в менеджере каталогов).

### Сериализация сканирования

Функция `runScan()` в main-процессе защищает от параллельных запусков:
- если сканирование уже идёт — устанавливается флаг `pendingScan`;
- по завершении текущего сканирования запускается ещё одно (если флаг был установлен);
- результаты публикуются в renderer через `scan:complete` после каждого прохода.

### Поведение при изменениях на диске

| Ситуация | Что происходит |
|----------|---------------|
| Добавлен новый файл в каталог | Добавляется в базу, генерируется превью |
| Файл изменён (mtime/size отличаются) | Обновляются `modifiedAt`, `size`, `createdAt` в базе |
| Файл удалён с диска | Удаляется из базы вместе со связями тегов; превью удаляется (по `thumbnailPath` и хэшу пути) |
| Файл перемещён/переименован | Воспринимается как «удалён + добавлен» (new path) |
| Каталог удалён пользователем через UI | Удаляются файлы каталога из базы, связи тегов, превью-файлы |

## Управление каталогами

Меню → «Управление каталогами» (CatalogManagerPopup):

- **Список** каталогов с путём и статистикой (фото/видео).
- **Добавить** — диалог выбора папки + фоновое сканирование.
- **Удалить** — удаление каталога, его файлов, тегов-связей, превью. Файлы на диске **не удаляются**.

## Теги

### Создание

1. TagManagerPopup: поле ввода + кнопка «Создать».
2. `createTag` — идемпотентен: если тег с таким именем существует (без учёта регистра), возвращается существующий. Имя тега приводится к **нижнему регистру**, поэтому «foo», «Foo» и «fOo» не создают дубликатов.
3. Созданный тег появляется в списке тегов.

### Поиск

- TagManagerPopup имеет поле поиска; `tags:search` возвращает до 30 результатов по подстроке без учёта регистра.
- После списка тегов в TagManagerPopup выводится общее количество существующих тегов («Всего тегов: N»).
- FullscreenViewer имеет автодополнение при добавлении тега: ввод текста → подсказки из `tags:search` + возможность создать новый.

### Применение к файлу

1. Полноэкранный просмотр файла → секция «Теги».
2. Выбор существующего тега или создание нового.
3. `applyTag` устанавливает связь `mediaTags` и обновляет `lastUsedAt` тега (тег поднимается в сортировке).
4. Тег можно убрать кликом по крестику — `removeTagFromMedia`.

### Удаление

TagManagerPopup → кнопка удаления.

- Если тег **не присвоен ни одному файлу** — удаление выполняется сразу.
- Если тег **присвоен хотя бы одному файлу** — поверх окна появляется всплывающее модальное окно подтверждения с именем тега и количеством файлов, которым он присвоен. Окно рендерится через портал в `document.body`, поэтому всегда видно поверх попапа, независимо от прокрутки списка тегов. Пользователь может подтвердить удаление (кнопка «Удалить»), отклонить («Отмена»), либо закрыть окно кликом по фону или клавишей Esc.
- При удалении удаляются сам тег и все его связи `mediaTags`. Удаление изменит результат фильтрации.

## Метатеги

Метатеги — автоматически вычисляемые теги, которые **не хранятся в базе данных** и **не экспортируются**. Они вычисляются на лету из свойств файла и не могут быть удалены или сняты с файла.

### Группы

| Группа | Метатеги | Правило |
|--------|---------|---------|
| **Год** | `2025`, `2026`, ... | Год из даты создания файла |
| **Время года** | `зима`, `весна`, `лето`, `осень` | 1 декабря — 28/29 февраля = зима; 1 марта — 31 мая = весна; 1 июня — 31 августа = лето; 1 сентября — 30 ноября = осень |
| **Тип файла** | `фото`, `видео` | По расширению файла |

### Отображение

- **FullscreenViewer** — метатеги отображаются **серым цветом** отдельно от обычных тегов.
- **TagManagerPopup** — метатеги показываются над полем поиска тега, **не построчно**, а друг за другом (горизонтальными рядами), разбитые на группы: год → время года → тип файла.
- **FilterBar** — выбранные метатеги отображаются серыми чипами.

### Фильтрация

Клик по метатегу (в FullscreenViewer или TagManagerPopup) добавляет его в фильтр на основном экране **так же, как обычный тег**. Метатеги участвуют в фильтрации («все»/«любой», AND/OR) наравне с обычными тегами.

## Фильтрация по тегам

### Интерфейс

- **FilterBar** — панель в левом нижнем углу. Показывает выбранные теги (включая метатеги серым) и переключатель режима.
- Теги в фильтр можно добавить:
  - из **TagManagerPopup** — клик по тегу (включая метатеги);
  - из **FullscreenViewer** — кнопка «Добавить в фильтр»;
  - из **FilterBar** — через селектор выбора тегов.

### Логика

- Режим **«все»** (англ. AND) — файл показывается, если у него есть **все** выбранные теги.
- Режим **«любой»** (англ. OR) — файл показывается, если у него есть хотя бы один из выбранных тегов.
- Переключатель «все»/«любой» появляется, когда выбрано больше 1 тега.
- Фильтрация выполняется в **main-процессе** (`ipc-handlers.ts`, канал `media:get`): renderer отправляет `MediaFilters { filter }`, main возвращает отфильтрованный список.
- Сортировка результата — по `createdAt`, новые сверху.

### Поведение

- Убрать тег из фильтра — клик по крестику в FilterBar.
- Очистить фильтр — удалить все теги (переключатель и панель скрываются).
- При изменении фильтра `AppContext.loadMedia()` перезагружает медиа.

## Просмотр медиа

### Сетка

- Карточки квадратные, размер ячейки автоматически подбирается от 100 до 200 px в зависимости от ширины контейнера.
- Виртуализация: рендерятся только видимые строки + 3 строки overscan; при скролле список пересчитывается.
- Видео помечается бейджем ▶.
- Если превью ещё нет — карточка-заглушка; при событии `thumbnails:ready` превью подставляется без перезагрузки сетки.

### Полноэкранный просмотр

1. Клик по карточке → FullscreenViewer (по индексу в текущем списке `mediaItems`).
2. **Фото**: `<img>` через `media-stream://`.
3. **Видео**: `<video>` с элементами управления через `media-stream://`.
4. **Навигация**:
   - стрелки **←** / **→** (или кнопки ◀/▶) — переход к предыдущему/следующему файлу, циклически по `mediaItems`;
   - **Esc** (или кнопка ✕) — закрытие.
5. Показывается информация: имя файла, путь, тип, размер, дата.
6. В viewer доступно управление тегами (см. раздел «Теги»).

### Информация о файле

Показываются поля из `MediaFile`: `name`, `path`, `type`, `size`, `createdAt`, `modifiedAt`.

## Генерация превью

1. После сканирования новые файлы ставятся в очередь `queueThumbnails`.
2. Очередь обрабатывается последовательно (один ffmpeg за раз).
3. Renderer получает `thumbnails:progress` — прогресс-бар `ThumbnailProgressBar` показывает процент и скрывается через 300 мс после 100%.
4. По готовности каждого превью `thumbnails:ready` обновляет карточку в сетке.
5. Превью кэшируются в `media-catalog-data/thumbnails/` — повторная генерация не выполняется.

## Эспорт и импорт

### Экспорт

Меню → «Экспорт» → системный диалог сохранения (файл `media-catalog-export-<timestamp>.json`).

Экспортируются: каталоги, теги, связи тегов, список файлов (пути + метаданные). Превью **не** экспортируются.

### Импорт

Меню → «Импорт» → системный диалог открытия.

Алгоритм:
1. Добавление каталогов из файла импорта.
2. Восстановление тегов (по имени).
3. Полное сканирование (файлы получают новые id).
4. Восстановление связей тегов **по путям файлов** (через отложенный механизм `global.__pendingImportMediaTags`).

> ⚠️ Файлы не копируются. Импорт работает только если файлы доступны на диске по тем же путям.

## Уведомления (Toasts)

- **info** — нейтральные сообщения.
- **success** — «Добавлено файлов: N», «Удалено файлов: N» (после сканирования).
- **error** — «Ошибка сканирования каталогов» и другие.

Тост автоматически исчезает через 4 секунды. Клик закрывает раньше.

## Инициализация после импорта

При старте приложения вызвается `populateMediaTagsAfterImport()`:

- если в `global` есть отложенные связи (`__pendingImportMediaTags`) и пути (`__pendingImportFilePaths`);
- для каждого пути ищется id файла в базе (сначала `path.normalize`, затем `path.resolve`);
- при совпадении применяется связь через `database.applyTag(mediaId, tagId)`;
- временные глобальные переменные очищаются.

Это закрывает гонку: связи тегов применяются только после того, как файлы появились в базе в результате сканирования.
