# CLAUDE.md — правила поддержки проекта

Этот файл задаёт обязательные правила для любого AI-ассистента (и человека),
работающего с проектом **Media Catalog**. Правила нужно проверять **при каждом
изменении кода** и держать документацию в актуальном состоянии.

Проект — **нативное приложение на C++20 и Qt 6** (ветка `native`). Прежняя
реализация на Electron + React осталась в ветке `main`.

## Обязанности

1. **Перед изменениями в коде** — прочитать и учесть:
   - `README.md` — общее описание проекта;
   - `docs/ARCHITECTURE.md` — слои, потоки, генерация превью;
   - `docs/DATA.md` — схема базы данных, превью, экспорт/импорт;
   - `docs/WORKFLOW.md` — сценарии работы;
   - `docs/BUILD.md` — сборка и упаковка;
   - этот файл.
2. **После изменений** — проверить, не противоречат ли они документации. Если
   противоречат — исправить документацию.
3. **При добавлении новых возможностей** — описать их в документации.
4. **При каждом наборе изменений** — внести запись в `CHANGELOG.md`.

## Куда что писать

| Что изменилось | Где обновить |
|----------------|--------------|
| Схема базы данных, новый запрос, изменение хранения | `docs/DATA.md` (схема и правила целостности) |
| Новый тип данных | `docs/DATA.md` (структура) и `src/core/MediaTypes.h` (код) |
| Новый или изменённый метод ядра, вызываемый из QML | `docs/ARCHITECTURE.md` (слой приложения) |
| Новый компонент QML, изменение компоновки | `docs/ARCHITECTURE.md` (компоненты и компоновка) |
| Изменение потоков, порядка завершения, работы с базой | `docs/ARCHITECTURE.md` (раздел «Потоки и синхронизация») |
| Изменение алгоритма сканирования или превью | `docs/ARCHITECTURE.md` + `docs/WORKFLOW.md` |
| Изменение экспорта/импорта | `docs/DATA.md` (раздел об экспорте) + `docs/WORKFLOW.md` |
| Новая возможность или сценарий работы | `docs/WORKFLOW.md` + раздел «Возможности» в `README.md` |
| Изменение структуры каталогов проекта | `README.md` (раздел «Структура проекта») |
| Изменение зависимостей, сборки, упаковки | `README.md` и `docs/BUILD.md` |
| Изменение набора тестов | `docs/ARCHITECTURE.md` (раздел «Тесты») и `README.md` |
| Любой набор изменений кода | `CHANGELOG.md` — новая запись |

Если сомневаетесь — обновите связанные разделы, чтобы они не противоречили друг
другу.

## Запрещено

- ✖️ Менять код, не добавив запись в `CHANGELOG.md`.
- ✖️ Менять код, не обновив документацию, если изменилось описанное поведение,
  структура данных или сборка.
- ✖️ Удалять или переименовывать разделы документации без необходимости.
- ✖️ Добавлять в документацию несуществующие возможности.
- ✖️ Оставлять в документации устаревшие описания после рефакторинга.
- ✖️ Менять `docs/DATA.md`, не сверившись с `src/core/CatalogDatabase.h` и
  `src/core/MediaTypes.h` (и наоборот).
- ✖️ Ссылаться в документации на файлы, которых нет в дереве проекта.

## Чек-лист перед завершением задачи

- [ ] Запись об изменениях добавлена в `CHANGELOG.md`
- [ ] Код соответствует документации (или документация обновлена под код)
- [ ] Новые возможности описаны в `docs/WORKFLOW.md` и/или `docs/ARCHITECTURE.md`
- [ ] Новые методы ядра и компоненты QML отражены в `docs/ARCHITECTURE.md`
- [ ] Структура проекта в `README.md` актуальна
- [ ] Раздел «Возможности» в `README.md` покрывает новые возможности
- [ ] В документации нет ссылок на удалённые файлы
- [ ] Тесты проходят: `ctest --test-dir cmake-build --output-on-failure`

## Формат документации

- Документация и `README.md` — на **русском языке**.
- `CHANGELOG.md` — на **английском языке**: дата и краткое описание набора
  изменений; одна запись — один набор изменений.
- Markdown, заголовки `##`/`###`, таблицы для перечислений.
- Ссылки между файлами — относительные (`[DATA.md](docs/DATA.md)`).
- Блоки кода и JSON — с указанием языка (```bash, ```json).
- Пути файлов — в обратных кавычках: `` `src/core/MediaLibrary.cpp` ``.
