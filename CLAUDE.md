# CLAUDE.md — Правила для Cline по поддержке документации

Этот файл задаёт обязательные правила для Cline (и любых AI-ассистентов) при работе с проектом **Media Catalog**. Cline обязан проверять эти правила **при каждом изменении кода** и поддерживать документацию в актуальном состоянии.

## Обязанности Cline

1. **Перед внесением любых изменений в код** — прочитать и учесть:
   - `README.md` — общее описание проекта;
   - `docs/ARCHITECTURE.md` — архитектура, IPC, потоки данных;
   - `docs/DATA.md` — форматы данных, хранение, экспорт/импорт;
   - `docs/WORKFLOW.md` — сценарии работы приложения;
   - этот файл (`CLAUDE.md`).

2. **После внесения изменений в код** — проверить, не противоречат ли изменения существующей документации. Если противоречат — **исправить документацию**.

3. **При добавлении новых фич** — **обязательно добавить описание в документацию** (в соответствующие разделы).

4. **При каждом изменении кода** — **обязательно внести запись в `CHANGELOG.md`** (короткое описание изменений).

## Когда обновлять документацию

Обновляйте документацию в **том же наборе изменений**, что и код. Не отдельным коммитом позже.

### Обязательно обновить, если изменялись:

| Что изменилось | Где обновить |
|---------------|-------------|
| Новый IPC-канал / событие / изменение сигнатуры | `docs/DATA.md` (таблица каналов), `src/shared/ipc.ts` (код) |
| Новый/изменённый тип данных | `docs/DATA.md` (структура json), `src/shared/types.ts` (код) |
| Изменение структуры каталогов/файлов | `README.md` (раздел «Структура проекта») |
| Новый компонент / изменение потока данных | `docs/ARCHITECTURE.md` (раздел компонентов/потоков) |
| Новая фича / сценарий работы | `docs/WORKFLOW.md` + пункт в «Возможности» README.md |
| Изменение механики хранения/сохранения | `docs/DATA.md` (механизм сохранения) |
| Изменение алгоритма сканирования/превью | `docs/DATA.md` + `docs/WORKFLOW.md` (сканирование, превью) |
| Изменение импорта/экспорта | `docs/DATA.md` (раздел экспорт/импорт), `docs/WORKFLOW.md` |
| Изменение зависимостей/сборки | `README.md` (Технологии, Сборка) |
| Изменение поведения UI-компонента | `docs/ARCHITECTURE.md` (таблица компонентов) |
| Изменение безопасности | `docs/ARCHITECTURE.md` (раздел «Безопасность») |
| Любые изменения кода | `CHANGELOG.md` (новый пункт с датой и описанием) |

Если сомневаетесь — обновите связанные разделы, чтобы они оставались непротиворечивыми.

## Запрещено

- ✖️ Менять код **не обновив** `CHANGELOG.md` — запись в changelog обязательна при каждом наборе изменений.
- ✖️ Менять код **не обновив** документацию, если изменение меняет описанное поведение/структуру/данные.
- ✖️ Удалять или переименовывать разделы документации без необходимости.
- ✖️ Добавлять в документацию несуществующий функционал.
- ✖️ Оставлять в документации устаревшие описания после рефакторинга.
- ✖️ Менять `docs/DATA.md` без проверки `src/shared/types.ts` и `src/shared/ipc.ts` (и наоборот).

## Чек-лист перед завершением задачи

Перед `attempt_completion` Cline обязан пройти чек-лист:

- [ ] Запись о внесённых изменениях добавлена в `CHANGELOG.md`
- [ ] Код соответствует документации (или документация обновлена под код)
- [ ] Новые фичи описаны в `docs/WORKFLOW.md` и/или `docs/ARCHITECTURE.md`
- [ ] Новые типы/каналы IPC отражены в `docs/DATA.md`
- [ ] Структура проекта в `README.md` актуальна
- [ ] «Возможности» в `README.md` покрывают новые фичи
- [ ] Отсутствуют ссылки на несуществующие файлы/разделы

## Формат документации

- Документация пишется на **русском языке**.
- `CHANGELOG.md` — на **английском языке**; запись — одна строка, не более **200 символов**, с текущей датой.
- Markdown, заголовки `##`/`###`, таблицы для списков каналов/компонентов.
- Ссылки между файлами — относительные (`[DATA.md](docs/DATA.md)` и т.п.).
- Блоки кода/JSON — с указанием языка (```json, ```bash).
- Пути файлов — в кавычках с обратными кавычками: `` `src/main/database.ts` ``.

## Быстрая карта документации

| Файл | Что описывает |
|------|--------------|
| `CHANGELOG.md` | История изменений: дата и краткое описание каждого набора изменений |
| `README.md` | Обзор, возможности, запуск, сборка, структура проекта, ссылки |
| `docs/ARCHITECTURE.md` | Архитектура: main/preload/renderer, компоненты, IPC-потоки, безопасность |
| `docs/DATA.md` | Данные: JSON-база, превью, импорт/экспорт, все каналы IPC |
| `docs/WORKFLOW.md` | Сценарии: сканирование, теги, фильтрация, просмотр, тосты |

> ⚠️ Этот файл — главный источник правил. Если какой-то из docs-файлов противоречит коду, Cline обязан **исправить docs-файл**, а не игнорировать правило.
